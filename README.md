# 跨国临床试验随机、撤药作废与揭盲控制台

源提示词摘要：研究中心按分层因素生成分层区组随机号；随机号发错不能直接改记录；撤药未首剂给药须说明原因，原随机号永久保留且不再分配，区组补发同组槽位重新平衡；两位协调员并发提交只能一人拿号，写盘失败可重试且号码不被占用；药品管理员只看发药标识，监察员能查原因但看不到治疗组，越权查看被拒绝；研究者揭盲后追加不可改写审计。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev      # 开发端口 62028
npm test         # 领域逻辑 + store 集成测试
```

## 业务规则

### 区组发号（`utils/randomization.ts`）

- 按「研究中心 × 年龄分层」各自维护区组链，区组大小 4，A/B 模板交替（ABAB/BABA），任意时刻两组计数差 ≤ 1。
- 中央随机号取全局单调游标，跨分层唯一、只增不复用；分层只决定 A/B 排列。
- 当前区组发满才开启新区组。

### 撤药作废（`stores/trial.ts#withdraw`）

- **未首剂给药**：必须填写原因；原槽位置 `voided`（编号与受试者痕迹永久保留、永不分配），同分层补发一个同治疗组的新槽位（`replacement` 标记），下一次发号全分层优先消化补发槽，区组发满时 A/B 严格相等。
- **已首剂给药**：记录为终止用药（`discontinue-after-dose`），编号随治疗事实保留，区组不补发、游标不前移。
- 首剂给药时间由「首剂」按钮显式登记，作为两种撤药路径的分界。

### 并发互斥与写盘事务

- 模块级 try-lock：两个发号请求同时进入临界区时，只有一个拿号，另一个立即收到「占用中、未分配号码」的提示，可安全重试。
- 发号全程先在内存快照上执行，唯一写盘点 `persist()` 失败时整体回滚快照：台账、游标、审计全部还原，号码不占用。
- 重试成功后追加 `write-recovered` 审计。页面「模拟下次写盘失败」开关可演练该路径。

### 角色隔离（`utils/permissions.ts` + `utils/audit.ts`）

| 能力 | 协调员 | 研究者 | 药品管理员 | 监察员 |
| --- | --- | --- | --- | --- |
| 区组发号 / 撤药 / 首剂 | ✅ | ✅ | ❌ | ❌ |
| 发药（只见发药标识 KIT-xxxx） | ❌ | ❌ | ✅ | ❌ |
| 揭盲 | ❌ | ✅（仅此角色） | ❌ | ❌ |
| 查看治疗组 | ❌ | 仅揭盲后 | ❌ | ❌（揭盲后也不行） |
| 查看撤药/揭盲原因 | ✅ | ✅ | ❌ | ✅ |

- 越权调用返回 `denied` 并追加 `access-denied` 审计（含操作人与试图执行的动作）。
- 审计流按角色脱敏：药管视图抹掉治疗组与原因，监察员视图抹掉治疗组、保留原因。

### 揭盲与审计（`utils/audit.ts`）

- 紧急揭盲强制填写原因，仅研究者可执行；已揭盲/已撤药状态拒绝重复揭盲。
- 审计只追加：每条记录含 SHA-256 哈希与 `prevHash`（哈希链），运行期 `Object.freeze`；页面「校验完整性」按钮可复算全链，任何字段改写都会在断裂点暴露。

### 离线队列

模拟离线提交进入待处理队列，联网后由授权角色确认入库；入库同样走互斥锁与写盘回滚。
